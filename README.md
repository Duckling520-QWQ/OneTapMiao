## 双通道 + Shizuku 兜底架构

不同应用对无障碍接口的「配合程度」不同，本应用按应用自动选择通道：

```
┌──────────────────────────────────────────────────┐
│ 通道① 无障碍服务（全自动，无感）                    │
│ 监听目标应用输入框，标点替换 / 喵尾 / 颜文字实时生效  │
│ 适用于：QQ 等开放无障碍节点树的应用                  │
├──────────────────────────────────────────────────┤
│ 通道② 隐形输入法 + 一键加喵（一键触发）              │
│ 部分应用（如微信）不开放节点树，此时通过输入法通道     │
│ 读写输入框：点一下悬浮窗「喵」按钮即完成              │
├──────────────────────────────────────────────────┤
│ Shizuku 直写兜底（可选增强）                        │
│ 自动启用并切换隐形输入法（实测 54ms 完成），         │
│ 写完自动切回原输入法——全程无需进系统设置手动切换     │
│ 不授权 Shizuku 时退化为手动切换，核心功能不受影响    │
└──────────────────────────────────────────────────┘
```

另有**通知栏「加喵」按钮**：不开悬浮窗也能从通知栏一键触发。

## 悬浮窗交互

- **悬浮「喵」按钮**：随时可点，微信里打完字点一下即加喵
- **结果气泡**：操作结果直接在悬浮窗下方弹出
  - 成功绿色、失败红色，**按结果区分停留时长**（成功 1.2s / 失败 3.5s——失败提示较长，留足阅读时间）
  - `FLAG_NOT_TOUCHABLE`：气泡不拦截触摸，弹出的瞬间照样打字
  - 2.2 秒位置自适应，自动淡入

## 应用选择器

不想手输包名？点「选择」从底部滑出**本机应用列表**：

- **图标 + 应用名 + 包名**三行信息，按中文拼音排序
- **实时搜索**：应用名、包名均可搜，大小写不敏感
- **多入口去重**：双开/小号应用不会出现重复条目
- **「已适配」标记**：加过的应用带徽章，不重复添加
- **图标缺失占位**：个别应用取不到图标时显示「首字 + 主题色圆角块」，不留空白
- **异步加载**：后台线程查询，主线程渲染，加载中显示提示，中途关闭对话框安全收场
- 长按已添加的包名可删除

## 三层结果反馈

任何操作的结果**保证可见**，三层互为兜底：

| 层 | 何时生效 | 说明 |
|---|---|---|
| 悬浮窗气泡 | 悬浮窗开着（点喵时必然开着） | 不受后台限制，位置就在手指边 |
| Toast | 应用在前台 | 常规补充 |
| 通知栏 | 失败 且 悬浮窗未开启 | 失败原因绝不静默丢失 |

**通知权限引导**：Android 13+ 通知为运行时权限，设置页内一键授权——先弹系统授权框，拒绝过一次后自动改为跳转系统设置通知页（系统不会二次弹窗，这个细节已处理）。

## 诊断系统

出问题不猜，看证据：

- **自检快照**：无障碍服务、总开关、处理模式、追加喵、颜文字、目标应用、Shizuku 就绪状态、输入法服务安装、悬浮窗权限——九项状态一屏尽览
- **运行日志**：连续重复自动折叠（无障碍每 200ms 扫描一次的刷屏，500 行压成 2 行），关键信息不再被淹没
- **日志复制**：正文可长按选中手选 + 「复制全部」一键全拷，直接贴给开发者
- **Shizuku 通道探测**：一键探测命令通道是否可用，失败时完整回传 stderr，原因写在明面上
- **失败可解释**：每种失败场景都有对应的提示文案（输入框不在焦点、未授权、通道不通……），绝不让用户对着黑盒猜

## 兼容性处理

| 系统行为变更 | 本应用的应对 |
|---|---|
| Android 14 禁读 Settings 输入法字段 | 判定逻辑以 InputMethodManager 为准，Settings 仅作兜底，异常静默降级 |
| Android 11+ 应用可见性限制 | Manifest 声明 `<queries>`（非权限，不弹窗），应用选择器可见全部桌面应用 |
| Android 13 通知运行时权限 | 设置页内引导授权，拒绝一次后自动转跳系统设置 |
| Android 10 后台 Toast 拦截 | 悬浮窗气泡（SYSTEM_ALERT_WINDOW）作为主要反馈通道 |
| Shizuku Process 非标准异常 | 命令等待兼容 `IllegalArgumentException`（Shizuku 实现）与 `IllegalThreadStateException`（标准约定） |

## 权限说明

| 权限 | 用途 |
|---|---|
| 无障碍服务 | 通道① 监听并改写**目标应用列表内**应用的输入框内容 |
| 输入法（IME） | 通道② 对不开放节点树的应用（如微信）通过输入法通道读写 |
| 悬浮窗（SYSTEM_ALERT_WINDOW） | 「喵」按钮与结果气泡 |
| 前台服务（FOREGROUND_SERVICE） | 让悬浮窗服务在后台常驻不被回收（Android 8+ 起后台服务必须走前台服务） |
| 通知（Android 13+ 需授权） | 加喵失败且悬浮窗未开启时告知原因；前台服务的常驻通知也需要它 |
| 振动（普通权限，无需申请） | 加喵成功时的轻微振动反馈（v1.1.0，可关闭） |
| 忽略电池优化 | 避免后台服务被系统回收导致改写中断 |
| **不申请 INTERNET** | **应用无法联网，数据不出设备** |

Shizuku 为可选增强（自动切换输入法），不授权不影响核心功能。

## 常见问题

**Q：微信里为什么要手动点「喵」？**
微信不向无障碍服务开放节点树，全自动通道拿不到输入框内容，这是应用侧的限制而非 bug。通道②（输入法读写）专门为此设计。

**Q：会读到我的聊天内容吗？**
本应用只能读取**目标应用列表内应用**的输入框文本，且处理过程仅在本机内存中完成——应用连 INTERNET 权限都没有，数据物理上出不了手机。诊断日志也只存在应用私有目录，由你主动复制才会离开设备。

**Q：Shizuku 是什么？必须要吗？**
Shizuku 是一个广泛使用的开源 shell 框架（GitHub: RikkaApps/Shizuku）。它只用于「自动启用/切换输入法」这个便利功能：不装它，去系统设置手动切换输入法同样能用，只是多两步操作。

**Q：会导致封号吗？**
存在风险。修改输入内容可能触碰目标应用的服务条款（见免责声明第 3 节）。请自行评估，建议在娱乐场景使用。

**Q：日志里全是「根窗口递归未找到输入节点」？**
无障碍服务在非目标应用（如桌面、微信）上的正常扫描记录，连续重复已自动折叠，可忽略。
